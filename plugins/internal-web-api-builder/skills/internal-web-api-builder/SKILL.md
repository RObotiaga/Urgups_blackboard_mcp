# Внутренний веб API → SDK, MCP и skill

Выполняй запрошенный объём: исследование, клиент, MCP, skill или их сочетание. Если у сервиса есть официальное API, сначала проверь, покрывает ли оно нужные действия. Для UI-операций, которых там нет, используй наблюдаемые запросы и ответы веб-приложения.

## Рабочий маршрут

1. **Определи покрытие.** Перечисли действия пользователя, роль, тип каждого действия (чтение или изменение), путь в UI и доступные источники. Для формулировки «все операции роли» обследуй разделы этой роли и веди список найденного и непроверенного; не превращай увиденный фрагмент интерфейса в обещание полного покрытия.
2. **Собери эталон.** Для каждой операции запиши запрос вместе с предшествующими шагами сессии и ответом. Раздели постоянные значения и значения, которые появляются только после входа, редиректа, загрузки формы или вкладки. Сохрани в проекте только очищенный снимок. При работе с HAR, CDP или открытой вкладкой прочитай [захват и сверку](references/CAPTURE_PARITY.md) и используй [шаблон доказательств](assets/API_EVIDENCE_TEMPLATE.md).
3. **Построй клиент.** Отдели транспорт, состояние сессии, протокол сайта и операции предметной области. Получай ссылки, CSRF, nonce и идентификаторы из текущих ответов сайта. Для разработки клиента и MCP прочитай [проектирование SDK, MCP и skill](references/SDK_MCP_SKILL.md).
4. **Сделай инструменты пригодными для агента.** Дай операциям конкретные имена и узкие схемы. Возвращай понятный результат и действие для восстановления после ошибки. Для изменяющих операций покажи план и выполняй запрос в рамках уже полученного разрешения пользователя; проверяй результат по ответу сайта.
5. **Сверь реализацию.** Для каждой заявленной операции сравни доступные уровни запроса и фактический ответ с браузерным эталоном. Помечай отдельно «совпадает», «расходится» и «нет эталона». Проверяй поведение MCP на реальной последовательности действий агента, если это нужно для задачи. Не называй всю HTTPS-сессию побайтово идентичной по совпадению URL или тела формы.
6. **Передай результат.** Документируй установку, учётные данные, список операций, подтверждённые свойства запросов и оставшиеся пробелы. В skill оставь порядок работы; детали API и частные случаи вынеси в references, повторяемый код — в scripts.

## Инварианты

- Работа в браузере служит источником наблюдений. Готовый клиент не должен зависеть от браузера, если пользователь запросил независимый SDK/MCP.
- Логин, пароль, cookies, токены, реальные идентификаторы аккаунта и содержимое файлов остаются вне репозитория, логов и ответов MCP. Для повторного запроса бери динамические значения из текущей сессии.
- Соблюдай ограничения пользователя по зависимостям. Если сетевой отпечаток браузера требует отдельного транспорта, фиксируй измеренное расхождение и выбранную зависимость; совпадение HTTP-заголовков само по себе не доказывает совпадение TLS.
- Запрос, который меняет данные, не воспроизводи ради захвата без разрешения на это действие. При отсутствии эталона обозначь степень готовности и конкретную недостающую проверку.
- Заканчивай с матрицей покрытия: операция → источник эталона → статус реализации → проверенные уровни совпадения → ограничение.
